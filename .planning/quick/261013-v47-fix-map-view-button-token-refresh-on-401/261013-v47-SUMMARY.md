# Quick Task 261013-v47: Map View button, 401 token refresh, map top bar, profile photo

Central `authFetch` in mobile `api.ts` (forced Firebase token refresh + single retry + deduped sign-out on persistent 401), socket auth-callback with one forced-refresh reconnect, `_id` to `id` normalization for listing search, map top bar offset by the status-bar inset, and profile photo `onError` fallback.

## What changed

**Task 1 (d67b0fb) - auth layer**
- `backend/src/middleware/auth.js`: `verifyIdToken` failure is now logged as `[auth] verifyIdToken failed: <code|message>` (never the token) and returns 401. The ban lookup is in a second try/catch: a DB failure returns 500 (`[auth] user lookup failed`) instead of masquerading as a 401. 403 banned branch and `requireVerified` unchanged.
- `backend/src/socket/chatHandler.js`: socket auth catch now logs `[socket auth] verifyIdToken failed: <code|message>`.
- `mobile/src/services/api.ts`: new `authFetch` (token, adds JSON Content-Type only for non-FormData bodies, so multipart is covered). On 401 with a current user: shared in-flight `getIdToken(true)`, retry exactly once; persistent 401 or non-network refresh failure calls a deduped `handleSessionExpired()` which only calls `signOut(auth)` (stores and socket are cleared by the existing onAuthStateChanged / RootNavigator path). `auth/network-request-failed` on refresh does not sign out. All 32 authed call sites go through `authFetch`; the `authHeaders` helper was removed; the only non-wrapper raw `fetch` is the web blob read in `appendFile`. Non-forced `getIdToken()` appears once (inside the wrapper).
- `searchListings` maps each row to `{ ...row, id: String(row.id ?? row._id ?? '') }`: this fixes the Map "View" button, Marker keys and the selected-pin highlight.
- `mobile/src/services/socketService.ts`: `auth` is now the callback form (token fetched on every connection attempt); `connect_error` with `Invalid token` / `Missing auth token` triggers one forced token refresh + `socket.connect()` (`forceRefreshNext` / `authRetryUsed`, reset on `connect` and `disconnectSocket`). Otherwise warns and gives up; the socket never signs out.

**Task 2 (9fc698e) - screens**
- `AppNavigator.tsx`: `MapDiscovery` screen gets `options={{ contentStyle: { backgroundColor: '#fff' } }}` (drops the stack `paddingTop` for this screen only).
- `MapDiscoveryScreen.tsx`: `useSafeAreaInsets()`; top bar `top: insets.top`, loading overlay `top: insets.top + 72`.
- `ProfileScreen.tsx` / `ViewProfileScreen.tsx`: `photoUri = mediaUri(...)`; `<Image key={photoUri} onError=...>` rendered only when `photoUri !== failedPhotoUri`; `onError` logs `console.warn('[ProfileScreen|ViewProfileScreen] photo failed', uri, error)` and records the failed URI (per-URI, so a new signed URL retries automatically). Fallback is a 36px bold purple initial letter (or `?`) in the existing 100x100 circle.
