<objective>
Fix four bugs from the second phone-test round, diagnosed and verified by the orchestrator (do not re-investigate root causes):

1. Map "View" button does nothing — `GET /api/listings/search` rows carry `_id` (no `id`), so `handleOpenDetail` bails on `!selectedListing?.id`, Marker keys and the `selected` comparison break.
2. "Invalid or expired token" alert when creating a post — stale ID token after a Firebase Auth emulator restart; backend swallows the verify error; the client never refreshes.
3. Map top bar ("Find housing" + Filter) overlaps the status bar.
4. Own profile photo not visible on ProfileScreen (Image renders, load fails on device; server URL verified fine).

Purpose: unblock the phone test — listing detail from the map, posting, a usable map header, and a diagnosable/self-healing profile photo.
Output: patched backend auth middleware + socket auth logging, a central `authFetch` in mobile api.ts, socket token refresh, map/profile screen fixes, and a rebuilt release APK.
</objective>
