<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| guest client → /api/requests | Untrusted request input (dates, intro, target listing) |
| host client → PATCH /api/requests/:id | Status mutation must be authorised to the listing host only |
| StayRequest.status → address reveal | Acceptance is the sole gate for exact-address disclosure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03-01 | Information Disclosure | Exact address reveal | critical | mitigate | getListingDetail reveals exactAddress only when an accepted StayRequest exists for the requesting guest; per-request check, no caching across users |
| T-02-03-02 | Elevation of Privilege | Accept/decline another host's request | high | mitigate | updateRequestStatus rejects unless request.hostUid === req.user.uid |
| T-02-03-03 | Elevation of Privilege | Requesting stay on own listing to self-reveal | high | mitigate | createRequest rejects when req.user.uid === listing.ownerUid |
| T-02-03-04 | Spoofing | Forged guest identity in request body | medium | mitigate | guestUid taken from the verified token, never the request body |
| T-02-03-05 | Denial of Service | Oversized intro message | low | mitigate | intro capped at 500 chars in schema + controller validation |
</threat_model>
