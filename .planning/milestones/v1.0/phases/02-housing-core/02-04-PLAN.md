<objective>
Deliver the 1:1 Direct Messaging slice end-to-end: a verified user opens another verified member's profile and sends a message request; the recipient accepts or declines it from an inbox; on acceptance a conversation opens and the two exchange real-time, persisted 1:1 messages; and every delivered message push-notifies an offline recipient. This is the final missing Phase 2 slice and completes MSG-01, MSG-02, and MSG-05.

Purpose: Direct messaging is gated by an explicit accepted request — a safety property of a women-only platform. The gate MUST be enforced server-side (in the socket handler and the message-history endpoint), not merely hidden in the UI, so no client can inject a DM into a stranger's inbox. This slice also stands up the codebase's first real-time screen (DirectMessageScreen) on top of the authenticated socket built in 02-01.
Output: MessageRequest + Conversation + Message models; message-request and conversation REST APIs with push; a store-first, gated DM socket handler; and the mobile compose / inbox / conversation-list / real-time chat screens that replace the Messages placeholder.
</objective>

<design_notes>
This slice uses two request-side concepts that mirror the 02-03 StayRequest loop:
- `MessageRequest` is the pending gate object (like StayRequest): senderUid, recipientUid, intro, status (pending/accepted/declined). Accept/decline is recipient-only, exactly mirroring StayRequest accept/decline.
- `Conversation` exists ONLY after acceptance. Its existence for a sorted participant pair IS the MSG-02 gate: the socket refuses to write a DM unless an accepted Conversation exists for both users. This keeps the gate a single, server-enforced invariant.
- `Message` is a separate collection (locked decision), keyed by conversationId, written BEFORE the socket emit (store-first, locked decision).
- DM room name is `dm:{sortedUid1}_{sortedUid2}` (server-sorted UIDs) so a client cannot fabricate a different room — reused from the 02-01 socket layer.
City group chat (MSG-04) and the CityGroupChatScreen are out of scope for this slice; do not add join:city / message:city handlers here.
</design_notes>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sender client → /api/message-requests | Untrusted request input (recipientUid, intro); sender identity must come from the token |
| recipient client → PATCH /api/message-requests/:id | Accept/decline must be authorised to the recipient only |
| any client → GET /api/conversations/:id/messages | Message history must be readable only by a conversation participant |
| any socket → message:dm event | A DM may be written only when an accepted Conversation exists for the pair |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-01 | Information Disclosure | Reading another user's conversation | high | mitigate | conversationController.getMessages rejects unless req.user.uid is in conversation.participants; message:new is emitted only to the sorted-pair dm room |
| T-02-04-02 | Elevation of Privilege | Message-request gate bypass (DM without an accepted request) | high | mitigate | message:dm writes only when a Conversation exists for the sorted pair (Conversation is created solely on accept); join:dm also refuses rooms without one; UI is not the gate |
| T-02-04-03 | Spoofing | Socket auth bypass / forged sender identity | high | mitigate | io.use() Firebase-token auth from 02-01 gates every connection; senderUid taken from socket.data.uid and never from the client payload; recipient/sender never trusted from the body |
| T-02-04-04 | Denial of Service | Push-spam via message flood | medium | mitigate | content capped at 2000 chars (schema + handler); push sent only to a recipient NOT currently in the room (fetchSockets check, per RESEARCH Pitfall 7); duplicate/again message requests rejected 409; per-message rate limiting deferred to Phase 3 (documented) |
| T-02-04-05 | Elevation of Privilege | Accepting/declining someone else's message request | high | mitigate | updateRequestStatus rejects unless request.recipientUid === req.user.uid (mirrors StayRequest host-only guard) |
