<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile client → /api/listings | Untrusted geo/query params and listing input cross here |
| listing DB doc → API response | exactAddress must not cross to non-accepted guests |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02-01 | Information Disclosure | exactAddress leak via search/detail | critical | mitigate | Explicit projection in searchListings ($project omits address) and getListingDetail (addressRevealed=false this slice); never spread raw doc (getProfile pattern, Pitfall 5) |
| T-02-02-02 | Tampering | Geo query manipulation (negative radius / out-of-range coords) | medium | mitigate | Validate lat [-90,90], lng [-180,180], radiusM clamped 1..50000 before $geoNear |
| T-02-02-03 | Elevation of Privilege | Unverified access to listings | high | mitigate | All /api/listings routes behind verifyFirebaseToken + requireVerified |
| T-02-02-04 | Denial of Service | Oversized photo uploads | medium | mitigate | multer 5MB/file limit + .array cap of 10 photos |
| T-02-02-05 | Information Disclosure | Address triangulation from coordinates | high | mitigate | location stores neighbourhood centroid only; exactAddress is a separate string, never a coordinate; client never reverse-geocodes |
</threat_model>
