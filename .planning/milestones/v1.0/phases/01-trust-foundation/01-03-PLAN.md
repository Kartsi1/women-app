<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → backend (multipart) | Untrusted image files cross here; size + MIME validated before storage |
| backend → Firebase Storage | Buffers streamed via Admin SDK to a protected path |
| Storage → admin panel | Documents exposed only via short-lived signed URLs (Plan 04) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Denial of Service | /verification-docs upload | medium | mitigate | multer `limits.fileSize = 5MB` per file rejects oversized uploads |
| T-03-02 | Tampering | direct device→Storage write | high | mitigate | all uploads routed through backend; Storage rules deny client writes (RESEARCH anti-pattern) |
| T-03-03 | Information Disclosure | ID document readable by anyone | high | mitigate | protected `verification/<uid>/` path, no public read; admin views via signed URLs only |
| T-03-04 | Input Validation | non-image / malicious file | medium | mitigate | reject mimetype not starting `image/` (ASVS V5) |
</threat_model>
