<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verified device → backend profile API | Only verified tokens may read/write profiles |
| profile photo → other users | Photos exposed via signed URLs, not public paths |
| requester → target profile | Block state must gate profile visibility |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Elevation | unverified access to profiles | high | mitigate | `requireVerified` guards all profile routes |
| T-05-02 | Information Disclosure | private fields (email) leaking via GET /:uid | medium | mitigate | getProfile returns an explicit public projection only, never the raw User doc |
| T-05-03 | Information Disclosure | viewing a profile that blocked you | medium | mitigate | getProfile 403s when requester is in target.blockedUsers |
| T-05-04 | Input Validation | oversized bio / non-image photo | low | mitigate | bio maxlength 500; photo mimetype must be image/*; 5MB limit |
</threat_model>
