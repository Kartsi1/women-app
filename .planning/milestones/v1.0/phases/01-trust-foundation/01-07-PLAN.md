## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verified device → backend safety API | Only verified users may block/report; actor identity from token |
| block state → profile/message access | Server-side enforcement, not client-side hiding |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | blocking on behalf of another user | medium | mitigate | block keys on `req.user.uid`; a caller can only modify their own blockedUsers |
| T-07-02 | Repudiation | anonymous/false reports | low | mitigate | every Report records `reporterUid` from the verified token for admin accountability |
| T-07-03 | Elevation | unverified users blocking/reporting | medium | mitigate | routes guarded by `requireVerified` |
| T-07-04 | Input Validation | report with no reason | low | mitigate | backend 400s a report missing `reason`; client disables submit until present |
</threat_model>
