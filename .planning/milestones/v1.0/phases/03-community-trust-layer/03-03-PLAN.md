<objective>
Deliver the blind-release review backend (REVW-01/02/03): eligibility-gated review submission, the lazy-on-read reveal gate, and revealed-only profile aggregation — with a held-out test proving the counterpart review text cannot leak before the reveal predicate fires.

Purpose: This is the trust-loop core and the phase's single most safety-sensitive surface. The reveal gate is a security invariant equivalent to phase-2 exactAddress hiding: the client is NEVER the gate. Mobile review surfaces (03-04) render the state this API computes; they add no gate logic.

</objective>
