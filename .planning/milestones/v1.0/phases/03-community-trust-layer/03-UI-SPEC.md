# Phase 3 — Community & Trust Layer: UI Design Contract

> Visual and interaction contract for Phase 3 frontend screens.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Requirements covered:** COMM-01, COMM-02, COMM-03, REVW-01, REVW-02, REVW-03
>
> **Safety principle:** Review text MUST remain hidden from the counterpart until the blind-release
> predicate is satisfied server-side. The client is NEVER the gate. Blind-waiting surfaces must
> communicate the wait honestly without revealing any content. This mirrors the phase-2 address-hide
> discipline and is a hard UI constraint derived from REVW-03.
>
> **Inherited design system:** All tokens, palette, typography scale, weights, spacing, and component
> idioms carry over unchanged from the phase-2 UI-SPEC. This file extends — it does not replace or
> diverge from — that baseline.

## Typography

Inherited from phase-2 UI-SPEC — no additions, no weight changes.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 28px | 700 | 1.2 | Screen titles ("Community", "Write a review", "Post detail") |
| Heading | 20px | 600 | 1.3 | Post author name in feed (when given prominence), section headers ("Reviews", "Comments") |
| Body | 16px | 400 | 1.5 | Post text, comment text, review text, input field text, button labels |
| Label | 14px | 400 | 1.4 | Like count, comment count, timestamps, star count label, "X days until reveal" hint, report link |

**Weight contract:** Regular (400) + Semibold (600) + Bold (700). Unchanged from phase 2.

> **Weight-count override (Phase 1–2 parity):** 3 weights (400/600/700) retained. Bold 700 is a locked
> baseline from shipped phase-1 and phase-2 screens. Reducing to 2 weights would break consistency.
> Visual debt documented per ui-checker override path (same as phase-2 UI-SPEC).

Button labels: Body size (16px) at Semibold (600).
Placeholders and muted text: Label size (14px), weight 400, color `#999999`.
Star rating numeric summary (e.g. "4.3 · 12 reviews"): Label size (14px), weight 400.

## Interaction Contracts

### Community feed (COMM-01, COMM-02, COMM-03)

**CommunityFeedScreen layout:**
- Screen title "Community" (Display/28px/700) in header
- `FlatList` of `PostCard` components, reverse-chronological, cursor-paginated (`?before=<lastId>`)
- Pull-to-refresh: `RefreshControl` with accent spinner; refetches first page
- FAB (bottom-right, 56×56dp, accent `#6200ea`, Ionicons `add` white icon): navigates to `CreatePostScreen`
- No empty state for feed until explicitly empty (see Copywriting)
- End-of-feed: "You've seen all posts" Label/14px muted, centered, 24px vertical padding

**PostCard interactions:**
- Tap anywhere on post body → navigate to `PostDetailScreen`
- Like button: idempotent toggle; optimistic update (count ±1, icon fill switches); API call in background; on error: revert + inline "Couldn't like post" toast
- Comment icon tap: navigate to `PostDetailScreen` with keyboard focused on `CommentInput`
- Report icon (flag, top-right of card, 44×44dp): opens bottom-sheet confirmation (mirrors phase-2 Decline pattern):
  - Sheet title: "Report this post?"
  - Reason picker: `TextInput` required (placeholder "What's the problem?")
  - "Send report" button (accent) / "Cancel" text link
  - On success: "Report sent. We'll review it." inline toast; post remains visible to reporter

**PostCard photo (optional):**
- Rendered between text body and like row
- Full card width, 200dp tall, `resizeMode: 'cover'`, no tap action in feed (tap navigates to detail where full photo is shown)

### Create post (COMM-01)

**CreatePostScreen layout:**
- Navigation header: "New post" title (Heading/20px/600) + "Cancel" text button left + "Post" button right
- "Post" button: accent text color when text non-empty; muted `#999999` and disabled when text empty
- `TextInput` multiline, autofocused, Body/16px, placeholder "What's on your mind?", flex:1 fills remaining height
- `PostPhotoAttachment` at bottom of screen above keyboard
- Character limit: 1000 chars; count shown as Label/14px muted bottom-right when > 800 chars remaining inverted (i.e., "847/1000")
- On submit: "Post" button disabled + loading (opacity 0.6, "Posting…"); error inline below input; success → pop screen + feed refetches

### Post detail / comments (COMM-02)

**PostDetailScreen layout:**
- Navigation header: "Post" title
- `ScrollView` (not FlatList) — post + all comments load together at MVP scale
- Full `PostCard` at top (text not collapsed, full photo shown at full width)
- "Comments" section header (Heading/20px/600) + count (Label/14px muted)
- `CommentRow` list
- `CommentInput` fixed at bottom; `KeyboardAvoidingView` wraps entire screen
- Comment submit: send icon button; disabled until text non-empty; optimistic add to list; on error: "Comment not posted — tap to retry" (Label/14px, `#d32f2f`)
- Report on comment: same bottom-sheet pattern as post report, with "Report this comment?" title

### Star rating input (REVW-01, REVW-02)

- 5 stars rendered horizontally, sm/8px gap between stars
- Tap star N: sets rating to N; stars 1..N filled (`#f9a825`), N+1..5 empty (`#dddddd`)
- No half-stars in MVP
- Minimum rating to enable submit: 1 star (rating=0 is unset; submit disabled)
- Read-only display variant: same rendering, no press handlers, used in `ReviewCard` and `ReviewSummaryBar`

### Review compose (REVW-01, REVW-02)

**ReviewComposeScreen layout:**
- Navigation header: "Leave a review" title
- Subject name + avatar at top (Body/16px Semibold, 40×40dp avatar)
- `StarRatingInput` (interactive) — required; no submit if rating=0
- `TextInput` multiline, Body/16px, placeholder "Share your experience…", min 20 chars enforced (count shown: "18/20 minimum")
- "Submit review" button (full-width, accent): disabled until rating ≥ 1 AND text ≥ 20 chars
- Immutability warning (Label/14px muted, centered, below button): "Reviews are final and cannot be edited after submission."
- On submit: button disabled + "Submitting…" (opacity 0.6); on success → pop screen; on error → inline error below button
- Entry point: deep link from a post-stay notification or from ReviewEligibleCard on profile / conversations

### Review blind-release surfaces (REVW-03 — SAFETY/TRUST-CRITICAL)

**Design principle:** mirror the phase-2 amber/green chip pair exactly. The amber chip communicates
"something is being withheld fairly" — the same honest, non-alarming signal used for address hiding.
The green chip signals resolution. Never reveal content before the predicate fires.

**State machine (computed server-side, surfaced client-side):**

| API state | Chip | Surface content |
|-----------|------|-----------------|
| `waiting` — reviewer submitted, counterpart has not; deadline not passed | `ReviewWaitingChip` (amber) | Reviewer sees own submitted review text (read-only, muted border); counterpart's slot shows chip only, NO text |
| `revealed` — both submitted OR `now >= checkOut + 14d` | `ReviewRevealedChip` (green) | Both reviews shown in full as `ReviewCard` |
| `eligible` — stay confirmed, neither has submitted | No chip | "Be the first to leave a review" prompt + CTA |
| `own_submitted_other_waiting` | `ReviewWaitingChip` (amber) + countdown hint | See waiting state above |

**Waiting state detail:**
- `ReviewWaitingChip` text: "Review submitted — waiting for [Name]" (or generic "Waiting for other party" if name policy is unclear)
- Below chip: countdown hint Label/14px muted: "Reviews reveal on [date]" — date computed client-side as `checkOut + 14 days`, formatted as "Jul 23" or "23 Jul" (locale-appropriate short date)
- Own submitted review: shown below the chip as a read-only card with `#f5f5f5` background + `#dddddd` border — clearly marked "Your review (submitted)" in Label/14px muted above it
- Counterpart slot: chip only, no preview, no hint of content

**Revealed state detail:**
- `ReviewRevealedChip` renders at top of review pair section
- Both `ReviewCard` components rendered below (own first, counterpart second, labeled "Your review" / "[Name]'s review" in Label/14px muted above each)

### Reviews on profile (REVW-01, REVW-02, REVW-03)

**ProfileScreen extension (new "Reviews" section below existing stats):**
- `ReviewSummaryBar` — shown when `revealedReviewCount > 0`; hidden otherwise (no "0 reviews" placeholder)
- "Reviews" section header (Heading/20px/600) — only rendered when there are revealed reviews
- `FlatList` (or mapped array) of `ReviewCard` — revealed reviews only, reverse-chronological, max 10 in profile view with "See all reviews" text link if more
- Empty state (when eligible but no revealed reviews yet): no section rendered — no "No reviews yet" copy (avoids false impression for new users)
- Pending own-review (eligible, not yet submitted): `ReviewEligibleBanner` — see Copywriting

## Accessibility Contract

Inherited rules from phase-2 UI-SPEC — applied to phase-3 components:

| Rule | Value |
|------|-------|
| Minimum touch target | 44×44dp — all interactive elements including each star, like button, report icon |
| All interactive elements | Must have `accessibilityLabel` prop |
| Icon-only buttons | Must have `accessibilityLabel` describing action (e.g. "Like post", "Report post", "Remove photo") |
| Like button | `accessibilityLabel="Like post"` (unliked) / `"Unlike post"` (liked); `accessibilityState={{ selected: isLiked }}` |
| Star rating | Each star: `accessibilityLabel="[N] star"` + `accessibilityRole="button"` in interactive mode |
| `ReviewWaitingChip` | `accessibilityRole="text"` + `importantForAccessibility="yes"` — same as `SafetyChip` |
| `ReviewRevealedChip` | `accessibilityRole="text"` + `importantForAccessibility="yes"` |
| Report icon | `accessibilityLabel="Report this post"` / `"Report this comment"` |
| FAB | `accessibilityLabel="Create post"` + `accessibilityRole="button"` |
| Destructive buttons | `accessibilityRole="button"` + label includes consequence (e.g. "Delete post permanently") |
